# Supabase local và migration

Thư mục này chứa cấu hình Supabase local, Supabase Studio và toàn bộ migration
của ứng dụng.

## Khởi động Supabase

Tại thư mục `supabase`, chỉ cần chạy:

```bash
cd ~/project/seafood-provenance-system/supabase
docker compose up -d
```

Compose sẽ khởi động PostgreSQL, Auth, REST, Realtime, Storage, API gateway,
Meta và Studio. Compose không tự chạy migration của ứng dụng.

Truy cập Studio:

```text
http://localhost:8001/project/default
```

Kiểm tra trạng thái và log:

```bash
docker compose ps
docker compose logs -f studio
```

## Dừng Supabase

```bash
cd ~/project/seafood-provenance-system/supabase
docker compose down
```

Lệnh này không xóa dữ liệu database. Ngày hôm sau chỉ cần chạy lại
`docker compose up -d`.

Không chạy `docker compose down -v` nếu muốn giữ dữ liệu, vì tùy chọn `-v` sẽ
xóa volume database và storage.

## Quy ước file migration

Mỗi file trong `supabase/migrations/` phải có cả hai phần `up` và `down`:

```sql
-- migrate:up
create table public.example (
  id bigint generated by default as identity primary key
);

-- migrate:down
drop table if exists public.example;
```

Tên file phải theo định dạng:

```text
<14-chữ-số-timestamp>_<tên-migration>.sql
```

Ví dụ:

```text
migrations/20260802120000_create_example.sql
```

Không sửa migration đã được chia sẻ hoặc áp dụng. Khi cần thay đổi schema, hãy
tạo một migration mới.

## Chạy migration up

Mỗi ngày chỉ cần khởi động Supabase bằng `docker compose up -d`. Chỉ sau khi
tạo một file migration mới mới chạy:

```bash
./migrate-up.sh
```

Script sẽ kết nối vào container database đang chạy, bỏ qua các migration cũ và
chỉ thực thi phần `-- migrate:up` của các file chưa được áp dụng.

Script sẽ đọc các file theo thứ tự timestamp và chỉ thực thi phần
`-- migrate:up` của những migration chưa được ghi nhận trong bảng lịch sử.
Migration đã áp dụng sẽ được bỏ qua.

## Rollback migration

Rollback migration mới nhất:

```bash
./migrate-down.sh
```

Rollback đúng một migration theo tên:

```bash
./migrate-down.sh -f 20260802120000_create_example
```

Có thể ghi đầy đủ đuôi `.sql`:

```bash
./migrate-down.sh -f 20260802120000_create_example.sql
```

Script yêu cầu xác nhận trước khi chạy phần `-- migrate:down`. Phần SQL down và
việc xóa bản ghi lịch sử được thực hiện trong cùng một transaction; nếu một
bước lỗi thì toàn bộ rollback được hoàn tác.

Khi chọn rollback một migration cũ, các migration mới hơn vẫn giữ trạng thái
đã áp dụng. Chỉ thực hiện nếu các migration mới hơn không phụ thuộc vào bảng,
cột, kiểu dữ liệu hoặc hàm bị migration đó xóa.

## Những lệnh không sử dụng

Dự án dùng cơ chế migration riêng, vì vậy không dùng các lệnh sau cho migration
của ứng dụng:

```bash
npx supabase migration up
npx supabase migration down
npx supabase db reset
```

Các runner migration và seed mặc định của Supabase đã được tắt trong
`config.toml` để tránh chạy cả phần `up` và `down` trong cùng một file.
